# Changelog

Two parts: the injection pipeline notebook `mol_fMRI_v5.x.ipynb` (below, newest version first; each version is a separate notebook, older notebooks stay unchanged) and the [electrical stimulation notebooks](#electrical-stimulation-notebooks) (at the end; not versioned, so the entries are dated).

## v5.8

Stable version (released 2026-11-26 after testing). Two new options, both off by default, so the notebook behaves as v5.7 unless they are switched on; when they are used, their quality-check figures have to be looked at.

### Added
- Automatic brain masks, chosen separately for the structural and the functional mask in two dropdowns at the top (hand-drawn in fsleyes stays the default; an existing mask is never replaced).
  - Structural mask: `3dSkullStrip -rat` combined with `3dAutomask` (`3dAutomask` alone if 3dSkullStrip fails). 3dSkullStrip alone can cut off the darker ventral brain along a straight line in images with a strong surface-coil intensity fall-off; 3dAutomask reaches the ventral edge, so the union is used. In tests against hand-drawn masks of 14 rat sessions (inside the slices covered by the hand-drawn mask) the overlap (Dice) was 0.97, lowest 0.96 (the same as 3dSkullStrip alone). It can be used after a look at the quality-check figure.
  - Functional mask: made from the structural mask (hand-drawn or automatic), which is moved to the functional grid through the image headers and trimmed with an intensity threshold. Dice 0.89 for EPI (lowest 0.72, 13 sessions) and 0.85 for sordino (3 sessions) with an automatic or a hand-drawn structural mask. Clearly less accurate: it always needs to be checked, and it is wrong if the animal moved between the two scans. Without a drawn cannula mask the brain mask is also used as the outline.
  - Quality check for automatic masks (`mask_quality_check`): overlay figures `mask_qc_structural.png` and `mask_qc_functional.png` (red = mask, cyan dashed = structural mask before the trimming) and warnings for separate pieces, empty slices, a mask at the image border, low edge contrast and, for the functional mask, a large change by the intensity trimming. The checks only catch gross failures; for functional masks they could not tell the weaker masks from the good ones, so the figure has to be looked at. Automatic masks are recorded in `<mask>.source.json`; a hand-drawn mask saved over an automatic one counts as hand-drawn again.
  - Tested on rat data only. The test scripts (`scripts/automask_test.py`, `scripts/automask_coreg_test.py`) are in the repository. With automatic instead of hand-drawn masks the functional → structural registration fitted equally well in 6 sessions (transforms differed by 0.4 mm and 2° on average).
- 3D automatic ROIs: the dropdown "Block depth" in the automatic ROI section makes the ROI a 3×3×3 voxel block over three consecutive slices instead of a 3×3 block in one slice (default). The whole block has to lie inside the striatum and the despeckled mask. The z-scores of 3D blocks are not comparable with those of the 3×3 blocks.

### Changed
- Automatic masks, revised for SORDINO (2026-11-25):
  - Structural mask: `3dAutomask` is only added within 0.4 mm (in-plane) of the `3dSkullStrip` mask instead of the full union, then the mask is opened in-plane (0.3 mm) and reduced to its largest connected piece. The full union took in both temporalis muscles in one SORDINO session (Dice 0.83 against the hand-drawn mask); now 0.94-0.96 in the 3 SORDINO sessions. This also applies to EPI sessions, where the full union had Dice 0.97 (14 sessions); the new version has not been re-tested there.
  - SORDINO slab: the 3D sordino volume contains the whole head, so for a SORDINO scan the automatic structural mask and the functional mask made from it cover only a slab of structural slices (`limit_mask_to_slab`): new fields "SORDINO slab (slices)" (default 20, 0 = all) and "slab shift" (default +3 slices towards anterior). The slab is centred on the widest brain slice plus the shift, which gave the striatum-centred 20-slice slab of the hand-drawn masks exactly or one slice off (3 sessions). A structural mask that spans no more slices (e.g. hand-drawn) is not changed.
  - SORDINO functional mask: no intensity trimming (sordino has almost no intensity edge at the brain border: inside/outside ratio 1.0-1.3, so the trimming removed nothing), and the structural mask is moved as a partial-volume fraction (a functional voxel is brain if at least 30% of it is covered) instead of nearest neighbour, which put the edge about half a voxel inside. Fully automatic Dice inside the slab 0.87-0.93 (3 sessions; before, with the hand-drawn structural mask: 0.86-0.92). The edge-contrast warning of `mask_quality_check` is off for sordino (`edge_warning`). EPI functional masks are made as before.
  - Still open: the mask is moved through the image headers only; in one sordino test session it was about one voxel off, probably because the animal moved between the scans. A bounded registration as a check is not implemented yet.
- Mouse atlas: Allen CCFv3 instead of DSURQE (shared with the stimulation notebooks, see v2.3 there).
- Window duration in **seconds** instead of volumes, entered next to the baseline and signal start volumes (not at the top any more). It is converted with the volume TR of the scan (`window_volumes`), so the same duration works for EPI and SORDINO; the number of volumes is shown next to the field. The notebook stops if a window runs past the end of the scan and notes overlapping windows. The window end is still included as before (the mean images cover the window volumes + 1).
- Removed the "Temporal Smoothing (in vols)" field: its value was not used since the early versions (no temporal smoothing is applied), and the start-point cell no longer calls the data it opens in fsleyes "temporally smoothed". The automatic ROIs use the caudoputamen for the mouse (the striatum of SIGMA for the rat, unchanged). A registration folder made with another atlas is moved to `previous_atlas_<date>/` and the registration is done again (`ensure_atlas_folder` in `electric_stim_atlas.py`).

## v5.7

### Added
- SORDINO scans (zero echo time, 3D radial) are supported next to EPI; the rest of the pipeline is unchanged. The sequence is detected from the `##$Method` entry of the Bruker `method` file of the functional scan (`detect_sequence_type`), can be forced with the new "Sequence" dropdown (auto/EPI/SORDINO), and is asked for if both give nothing.
- `set_volume_tr`: for a sordino scan the converted `func.nii.gz` gets the real volume TR written into its header (`PVM_ScanTime / PVM_NRepetitions`, e.g. 2.4 s for 3200 spokes). Bruker only stores the 0.75 ms spoke TR in `PVM_RepetitionTime`, so brkraw writes a wrong TR (1 s). The fix (AFNI `3drefit -TR`) changes the header in place and never touches the voxel data, so it also repairs an existing conversion and is safe to re-run.

### Changed
- Distortion correction cannot be selected for a sordino scan (no echo-planar readout, so no EPI distortion); the parameter cell stops with an error.
- The coregistration of a sordino scan is rigid body only: there is no phase-encoding axis, so the optional scaling along it (see v5.5) and its axis detection are skipped.
- The volume TR (`tr`) is a float instead of an integer, so 2.4 s is no longer truncated to 2 s.

### Notes
- The baseline/signal start indices and the window size are still given in volumes, and a sordino volume covers more time than an EPI volume. Adjust the defaults for sordino.
- Several back-to-back sordino scans are not stitched in this notebook; use the `mol_fMRI_sordino_*` notebooks for that.

## v5.6

- The brain edge for the exclusion mask and for the coregistration is the outline that includes the cannulas (`mask_outline_with_cannulas.nii.gz`, from `mask_mean_mc_func_cannulas.nii.gz`), so the notch where a cannula enters the brain is not trimmed as if it were a brain edge. The candidate voxels (`mask_exclusion_candidates.nii.gz`) are the brain voxels inside that outline after the 2-voxel line-wise shrink; the cannula path itself stays excluded. The coregistration uses `cleaned_outline_mean_mc_func.nii.gz`. Without a cannula mask the brain mask is used, as before.
- Despeckled maps are saved alongside the existing ones, which stay untouched. `mask_despeckled.nii.gz` is the exclusion mask without speckle: small in-plane clusters (fewer than 5 voxels) that reach 3 noise SDs of PSC, and voxels above 2 noise SDs whose time course correlates with their in-plane neighbours with r < 0.3 (gaps of up to 4 voxels that only this check would create are filled again). It gives `clean_despeckled_scm_from_sm_*.nii.gz` and, in structural space, `despeckled_signal_change_map_coregistered_structural_space.nii.gz`, where clusters smaller than one functional voxel (in mm²) are removed in addition. The limits are arguments of `create_despeckled_mask` in the signal change map cell.
- Existing results are not overwritten silently: if a result already exists (motion correction, smoothed data, coregistration), you are asked whether to overwrite it, and Enter keeps it. A result that is older than its input is marked OUTDATED and then Enter overwrites it. Set `OVERWRITE_POLICY` in the step-selection cell to `"never"` or `"always"` to skip the question. Derived maps and masks inside the dated result folder (signal change maps, exclusion mask, structural-space masks) are cheap and are always recomputed. Hand-drawn masks and the converted func/struct NIfTI files are never overwritten (an existing conversion is skipped).
- `coregistration_afni` removes its old output files before it runs. `3dAllineate` refuses to overwrite them without any error, so a re-run could leave an outdated coregistered signal change map next to a new transform.
- Optional cells at the end run `exclusion_diagnostics`: which exclusion rule (and the shrunk mask and structural restriction) removes which voxels, with a figure of all slices (`exclusion_diagnostics.png`), a reason map (`exclusion_reason_map.nii.gz`) and a report. If ROIs exist, it also shows how much of each ROI, and of voxels with a similar time course, is lost. It changes no map or mask.
- Optional automatic ROIs (before the ROI cell): per side, the 3×3 voxel block (one slice) with the strongest signal change inside the striatum of the SIGMA rat atlas replaces drawing the ROIs by hand. The protein/sensor, delivery route (AAV or direct) and the acutely injected substance are asked for in a small form and go into the ROI file names. The selection is described in the cell and written to `automatic_roi_summary.txt`; `automatic_roi_qc.png` shows the striatum outlines and the chosen blocks.

## v5.5

- Motion correction: two passes (cubic, then heptic against the mean of pass 1), brain-weighted, no more `-linear`.
- Spatial smoothing is done inside the brain mask (normalized convolution) before the signal change maps are computed.
- The exclusion mask (`mask_thresholded.nii.gz`) replaces the 15–80 percentile cut. A voxel is kept only if it is at least 3 voxels from the brain edge, has a baseline of at least 50% of the median, and a baseline tSNR (`tsnr_baseline_*.nii.gz`) of at least 60% of the median. The mask is moved to structural space with the coregistration affine (`struct_mask_from_functional.nii.gz`) and intersected with the structural brain (`struct_mask_final.nii.gz`), which removes the isolated dead voxels inside clusters and the voxels outside the structural brain.
- A coregistration quality check (`coregistration_qc`) compares the registration with a header-only alignment, warns about implausible transforms, and writes `coregistration_qc.png` (overlay) and `coregistration_qc.txt`. It only reports; it does not change the transform.
- Coregistration may scale the functional image along the phase-encoding axis (within 0.92–1.08, rotations ≤ 5°, shifts ≤ 2 mm) to compensate EPI stretching. The axis comes from the "Phase-encoding axis" dropdown or is detected from brkraw's BIDS sidecar (cached in `func.detected_pe.json`); the scaling is switched off when distortion correction is used or the axis is unknown.

## Scripts

### plot_slice_stack.py (2026-11-20, rebuilt after the deConfUSIon viewer)
Rebuilt to work like the 3D viewer of the deConfUSIon toolbox (`fusiVolumeGUI.m`, github.com/SonerCgu/deConfUSIon), on the Allen CCFv3 template for mouse maps:
- **Volume rendering** is one colour volume, as in deConfUSIon: the anatomy is a faint blue-gray haze whose opacity is set for the whole brain (`--atlas-opacity`, default 0.8 along the longest path through the brain), the map gets an opacity that rises with the value (square-root lifted, times `--strength`, default 5), and the anatomy is dimmed around strong responses. It is rendered with VTK's CPU ray caster, which applies the opacity per voxel like MATLAB's `volshow`; the GPU renderer used before ignored it for colour volumes, which is why the old volume looked like slices put together. The opacity is stored as its cube root, so the very small per-voxel opacity of the anatomy keeps its precision in 8 bit.
- **Slice stack:** every slab (mean of `--slab-slices` atlas slices, default 5 × 50 µm) is a flat tile with a front and a back face (the old slabs looked empty from behind) and side walls along the exact outline of the brain; tiles side by side, each rising a little (`--tile-gap`, `--tile-rise`; more than 6 tiles are split into strips), parallel camera "paper oblique" (yaw −6°, tilt 8°), labels with position and thickness, 500 µm scale bar. `--projection max` shows the largest value of the slab instead of the mean (better for sparse maps).
- **Surface rendering:** translucent brain surface with the map as unsmoothed voxels in their exact colours (`--surface-mode voxels`, default) or as a smooth contour.
- Black background and the FSLeyes "blackbdy_iso" colours by default (`--background`, `--cmap`); the colour scale starts at 0 (`--color-min`), values below `--threshold` are hidden. The map is only shown in the measured region (`brain_mask_atlasspace.nii.gz` next to the map, or `--coverage`).
- The anatomy and brain mask are found from the analysis folder (`atlas_used.json`): the Allen template for mouse maps, the registration template otherwise; `--underlay` sets it by hand. The call is now `plot_slice_stack(map_file, out_file, ...)` (the anatomy became the keyword `underlay_file`).
- Output as before: figure with colorbar, interactive window (`--interactive`; `s` saves the view), rotating video (`--movie`); the form has new fields for all settings.
- Tested on a mouse t-map registered to the new Allen atlas and on a synthetic map, all three views, video and interactive window.

### tools/build_allen_atlas.py (2026-11-20)
- New: makes the mouse atlas files in `atlas/Allen_DevCCF_P56/` from the DevCCF P56 download (Kronman et al. 2024, CC BY 4.0): the T2w MRI template and brain mask for the registration, the 316 Allen summary structures (Allen structure set 167587189, cortical layers merged) split at the midline (right 1–316, left 1001–1316) with a names CSV, and the Allen CCFv3 template on the same 50 µm grid for figures. The coordinate origin is moved to the centre of the brain (DevCCF has it in a corner, far from the animal scans; the registration corrects large shifts only left-right and up-down by the centre of mass). `--download` fetches the files.

## Electrical stimulation notebooks

The notebooks for the analysis of electrical stimulation experiments (since v2.4: `mol_fMRI_electric_stim_preprocessing_v2.4.ipynb` and `mol_fMRI_electric_stim_analysis_v2.4.ipynb` for EPI and SORDINO; up to v2.3: `mol_fMRI_electric_stim_*.ipynb` for EPI and `mol_fMRI_sordino_*.ipynb` for SORDINO, now in `archive/v2.3/`; with `electric_stim_helpers.py`, `electric_stim_session.py`, `electric_stim_atlas.py`, `sordino_helpers.py`, `brain_masks.py`) have **one version number for the whole set**, EPI and SORDINO together. It is the constant `STIM_NOTEBOOKS_VERSION` in `electric_stim_session.py`, printed by the first code cell of every notebook and saved as `stim_notebooks_version` in the `session.json` of every preprocessing run (an analysis notebook notes if a session was preprocessed with another version). A change of the notebooks gets a new version here and a new value of the constant.

Versions up to 2.1 were assigned afterwards from the git history (the dates are those of the commits; several commit messages are only "minor changes", so those entries only say which notebooks were touched). See [docs/electric_stim_analysis.md](docs/electric_stim_analysis.md) for the description of the notebooks.

### v2.4 (2026-11-26)
Two notebooks for EPI and SORDINO replace the six v2.3 notebooks. Released as the stable version on 2026-11-26 (after testing): `STIM_NOTEBOOKS_VERSION` is 2.4 and both notebooks take their version from it. The six v2.3 notebooks were moved unchanged to `archive/v2.3/` (they import the helper modules from the root folder: copy a notebook back to run it; it would then print version 2.4).
- **`mol_fMRI_electric_stim_preprocessing_v2.4.ipynb`: one preprocessing notebook for EPI and SORDINO.** The sequence is detected from the `##$Method` entry of the first functional scan (`detect_sequence_type`, added to `sordino_helpers.py`, as in `mol_fMRI_v5.8`) or chosen in the new "Sequence" dropdown; all stitched scans must have the same sequence. The sequence-specific steps are unchanged: EPI needs at least 2 scans, stitches with `fslmerge -t` and can be distortion corrected; SORDINO takes 1 scan or more, stitches with the real volume TR (`merge_with_tr`) and prints the trigger blocks. "Volumes to drop per scan" is empty by default and then uses the default of the sequence (EPI 10, SORDINO 0). `session.json` gets the keys of both old notebooks (EPI: `distortion_correction`, `rev_pe_scan_number`; SORDINO: `scan_info`) plus `sequence_type` and `mask_sources`, so the v2.3 analysis notebooks can also load these sessions (and the v2.4 analysis notebook loads sessions of the v2.3 preprocessing notebooks). The EPI `tr` is now a float (was truncated to an integer).
- **Automatic brain masks** in the preprocessing: "Structural mask" and "Functional mask" dropdowns (hand-drawn in fsleyes stays the default; an existing mask is never replaced), SORDINO slab fields, quality-check figures `mask_qc_functional.png` / `mask_qc_structural.png`. Same methods as `mol_fMRI_v5.8` (see there for the test results); the functions are copied unchanged into the new module `brain_masks.py`. The functional mask is made before the motion correction, on the mean of the 30 volumes around the middle of the stitched series (`auto_mask_reference.nii.gz`). Always look at the quality-check figures; the functional mask is wrong if the animal moved between the structural and the functional scan. The structural mask needs a standard anatomy of the same session (on a 700 × 700 anatomy 3dSkullStrip failed).
- **`mol_fMRI_electric_stim_analysis_v2.4.ipynb`: one analysis notebook for EPI and SORDINO** with the stimulation response (from `mol_fMRI_electric_stim_analysis` / `mol_fMRI_sordino_analysis`) and the post-stimulation analysis (from the two `..._poststim_analysis` notebooks) as two parts, each with a tick in the first cell so either can run alone. The session, the motion-corrected series and the atlas registration (`register_to_atlas`, the same registration as before, into the same `roi_atlas_<species>/` folder) are loaded / done once. The sequence comes from `session.json` (older sessions: `scan_info` or the method file). Outputs and file names are unchanged. Differences to v2.3:
  - Stimulation response: EPI and SORDINO share the region and map code; only the epoch definition differs (EPI: method-file epochs, baseline = pre-stimulation baseline, comparison = the rest right before each onset; SORDINO: trigger blocks, baseline and comparison = the OFF window at the end of each block). The EPI ON/OFF split (40 / 20 s) and the rest window are now input fields instead of constants. `atlas_roi_stim_response.csv` has `on_psc` and `rest_psc` for SORDINO too (were EPI only). The response map and the native stimulation maps are saved as float32 (`save_map`; before they took the integer data type of the label image header). The EPI results were checked to be the same as with the old code on synthetic data.
  - Post-stimulation: the window duration is entered in **seconds** (converted with the volume TR, the number of volumes is shown), also for EPI; the EPI defaults are now 50 s / 300 s instead of 50 / 300 volumes (the same for a TR of 1 s). The EPI TR is taken from `session.json` if it is there.

### v2.3 (2026-11-20)
- Mouse atlas: **Allen CCFv3 instead of DSURQE.** The structural scan is registered to the DevCCF P56 T2w MRI template (MRI to MRI, same settings as before: brain-masked, 0.1 mm, scaling, `nmi`), which contains the Allen CCFv3 template and annotation; the regions are the 316 Allen summary structures split into left and right (`*_L` / `*_R`, names like "Primary somatosensory area, barrel field_L"). Files made once with `tools/build_allen_atlas.py`. On the test animal (RGRO_260915_0224_BL6_1364) the registration needed less scaling than with DSURQE (y-scale 0.91 instead of 0.73, 1.5° instead of 12° tilt) and the atlas brain overlapped the functional brain mask better (Dice 0.90 instead of 0.87). Results of mouse analyses made with DSURQE have other region names and ids and are in another atlas space; do not mix them.
- The analysis notebooks take the atlas settings from `electric_stim_atlas.species_atlas_config` (they had their own copy).
- A `roi_atlas_<species>/` folder records its atlas in `atlas_used.json`; a folder made with another atlas (or before this version) is moved to `previous_atlas_<date>/` and the registration is done again, so an old registration is never combined with new labels.
- Atlas labels QC: the coverage and the Dice are computed with the brain mask of the atlas (if it has one) instead of "labels > 0", because the Allen regions leave fibre tracts and ventricles unlabelled; the share of voxels with a region label is reported as well.

### v2.2 (2026-11-19)
- Version numbers for the stimulation notebooks (see above). Sessions made before this version show "unknown (made before version numbers)".
- `mol_fMRI_sordino_analysis.ipynb`: the stimulation timing that is not stored in the data is entered in a new input cell instead of being fixed in the code: Stimulation ON (required, no default, so a wrong value is never used silently), Stimulation OFF (default: the rest of the trigger block), hemodynamic lag and the OFF window at the end of the block. The trigger blocks read from the method files are shown next to it.
- `mol_fMRI_sordino_analysis.ipynb`: a trigger block that is at least twice as long as the shortest one (e.g. 500 volumes after ten blocks of 25 volumes) is the post-stimulation phase of the same scan and is no longer counted as an additional epoch. This allows one scan per stimulation with the stimulation blocks and the post-stimulation phase together.
- `mol_fMRI_sordino_poststim_analysis.ipynb`: if the last scan ends with such a long trigger block, the default baseline window starts at the beginning of the post-stimulation phase and the signal window ends at the end of the scan (the window length is at most half of the phase).
- 2026-11-17: standalone scripts (`mol_fMRI_electric_stim_stitching.py`, `mol_fMRI_sordino_stitching.py`, `roi_atlas_analysis.py`) moved to `scripts/`; self-contained old notebooks moved to `archive/`. The notebooks still import the helper modules from the root folder.
